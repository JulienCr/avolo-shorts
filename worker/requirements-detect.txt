# Ce que `worker/detect.py` demande.
#
# **Un second venv, et c'est délibéré.** `WHISPER_PYTHON` pointe le venv du
# diariseur de `~/dev/rythmo-impro/diarizer`, qui appartient à un autre dépôt et
# porte un correctif porteur (`LD_LIBRARY_PATH` vers son `nvidia/cudnn/lib`, sans
# quoi CTranslate2 ne charge rien). Y installer ultralytics reviendrait à faire
# résoudre à pip les contraintes de WhisperX et celles d'ultralytics dans le même
# arbre : la première montée de version qui déplace `torch` casserait la
# transcription, et le dépôt qui la porte n'est pas celui-ci. Les quelques
# gigaoctets de `torch` en double sont le prix de cette isolation.
#
# `setup.sh` monte ce venv dans `worker/venv` et vérifie que CUDA y répond
# vraiment. Pour le faire à la main :
#
#     python3 -m venv worker/venv
#     ./worker/venv/bin/pip install --extra-index-url https://download.pytorch.org/whl/cu128 \
#         -r worker/requirements-detect.txt
#
# **Les versions sont épinglées en `==`**, comme dans `requirements.txt` et pour
# la même raison (spec §5) : ce sont celles sur lesquelles la détection a
# réellement tourné, le 18 août 2026.
#
# L'index PyTorch est celui des roues CUDA 12.8. Sans lui, pip installe la
# variante processeur de `torch`, qui s'importe très bien, ne voit pas le GPU, et
# fait passer la détection de cinq minutes à plusieurs heures sans un mot. C'est
# exactement ce que la vérification de `setup.sh` cherche à attraper.
#
# `torchvision` n'est pas une dépendance déclarée d'ultralytics mais lui est
# indispensable (NMS, transformations) ; l'épingler ici évite que pip aille
# chercher une variante processeur pour satisfaire une version de `torch` qu'il
# aurait choisie tout seul.

torch==2.8.0
torchvision==0.23.0
ultralytics==8.4.121
