# avolo-shorts — Itération 0 : le squelette qui marche

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

## Contexte

Julien tire des extraits courts des replays Twitch de « LA SCÈNE AVOLO ». OpenShorts,
l'outil actuel, résout un autre problème : il suit un sujet là où il faut cadrer une
scène, détecte des visages là où les comédiens jouent de profil, et ne sort que du
9:16 — or seuls 24 à 33 % du temps tiennent dans un 9:16, contre 48 % jusqu'au 1:1.

Ce plan construit **l'itération 0 et rien d'autre** : la chaîne complète en état de
marche, interface comprise, avec le cadrage réglé à la main. Une sortie moyenne mais
entière apprend plus qu'un étage parfait qu'on ne peut pas encore regarder.

**Goal:** ingérer un replay local, le transcrire, en proposer des candidats via Gemini,
les trier et les monter dans le transcript, et exporter un MP4 sous-titré — de bout en bout.

**Architecture:** un seul app Next.js. Toute la logique de décision est du TypeScript pur
dans `src/core/`, testé en CI sans GPU ni ffmpeg. `src/server/` porte ce qui touche au
disque, à SQLite et aux processus. Un worker Python ne fait que WhisperX. ffmpeg est
piloté par Node.

**Tech Stack:** Next.js (App Router) · TypeScript · Vitest · better-sqlite3 · shadcn/ui sur
Base UI · TanStack Query · TanStack Virtual · Zustand · ffmpeg (NVENC) · WhisperX ·
`@google/genai`

**Spec:** `docs/superpowers/specs/2026-08-17-avolo-shorts-design.md` — fait autorité, à lire
avec ce plan.

## Global Constraints

- **Le clip est une liste de segments.** `{ segments: [{start, end}, …] }`. Écrire
  `{start, end}` au niveau du clip casse le produit. La durée est **un résultat**, jamais
  une entrée. Pas de plafond de durée nulle part.
- **`src/core/` est pur** : aucun `node:fs`, `node:child_process`, `next/*`, aucun accès
  réseau. Règle ESLint qui échoue le build. C'est la leçon d'openshorts, dont le `main.py`
  importe `torch` au chargement et dont le CI n'a jamais tourné une seule fois.
- **Le CI doit tourner** dès la première PR. `pnpm test` + `pnpm type-check` + `pnpm lint`.
- **Pas de Docker** (spec §5). Node natif, Python en venv, ffmpeg natif.
- **Le dépôt est public.** Aucune clé, aucun media, aucun transcript dans git. Le
  `.gitignore` de `chore/repo-setup` couvre déjà `/projects/`, `/stage/`, `*.mp4`, `.env`.
- **Sauter l'étape si l'artefact existe** — présence de fichier, pas encore de clé de
  validité (spec §4). `force` court-circuite.
- **Le transcript vit dans un sidecar** à côté de la source, pas dans le projet.
- Marqueurs `[SECONDS]` **tronqués, jamais arrondis**.
- Livraison : worktree isolé par tâche, PR vers `main` sur `JulienCr/avolo-shorts`.

## Ce qui est mesuré sur cette machine

Chiffres relevés le 18 août 2026, source `2026-03-08-caro-mdlm.mp4` (12,7 Go, 2 h 50, 1080p60).

| Étape | CPU x264 | NVENC 4090 |
|---|---|---|
| Proxy 960x540@30 | **13,8x** → ~12 min | 12,8x (plus lent) |
| Export → 1080x1920 | 1,97x | **4,58x** en `p5`, 7,51x en `p4` |

> **Deux chiffres de la première passe étaient faux, remplacés ici.** L'export
> NVENC était annoncé à **5,76x** : il a été relevé avec le ffmpeg **de
> Windows**, qui ne traverse pas la passerelle CUDA de WSL. Refaite avec le
> binaire Linux — celui que le projet appelle —, la mesure donne **4,58x** en
> `-preset p5`, de façon reproductible ; `p4` monte à 7,51x, à qualité non
> évaluée. Le CPU, lui, retombe sur sa valeur d'origine (1,97x contre 2,02x),
> donc ce n'est pas la machine qui a changé de rythme. Le repère à retenir est
> **4,6x**. Le proxy, lui, passait pour un gain nul du GPU ; il est en fait une
> perte, l'encodeur n'étant pas son goulot.

- Incrustation de texte : **coût nul** (2,02x → 2,12x, dans le bruit).
- Le montage 3 segments par `-ss` avant chaque `-i` puis filtre `concat` : **validé**,
  36 s produites en 10 s, bornes exactes, pas de décodage depuis le début du fichier.
- ffmpeg WSL 7.1.1 : libass **oui**, `h264_nvenc` **non**, `-hwaccel cuda` **non**. D'où la tâche 0.
- Les sources ne sont pas toutes en 60 fps : `2025-06-15-cqlp.mp4` est en 30. Le proxy
  normalise à 30 dans les deux cas.

- [ ] **Step 3 : Implémenter**

```ts
export function normalizeSegments(segments: Segment[]): Segment[] {
  const sorted = segments
    .filter((s) => s.end > s.start)
    .sort((a, b) => a.start - b.start)

  const out: Segment[] = []
  for (const s of sorted) {
    const last = out[out.length - 1]
    if (last && s.start <= last.end) last.end = Math.max(last.end, s.end)
    else out.push({ ...s })
  }
  return out
}

export function removeRange(segments: Segment[], from: number, to: number): Segment[] {
  const out: Segment[] = []
  for (const s of segments) {
    if (to <= s.start || from >= s.end) { out.push({ ...s }); continue }
    if (from > s.start) out.push({ start: s.start, end: from })
    if (to < s.end) out.push({ start: to, end: s.end })
  }
  return normalizeSegments(out)
}

export function moveBoundary(
  segments: Segment[], edge: 'start' | 'end', to: number,
): Segment[] {
  if (segments.length === 0) return []
  const out = segments.map((s) => ({ ...s }))
  if (edge === 'start') out[0].start = to
  else out[out.length - 1].end = to
  return normalizeSegments(out)
}
```

```ts
export function retimeWords(words: Word[], segments: Segment[]): Word[] {
  const segs = normalizeSegments(segments)
  const out: Word[] = []
  let elapsed = 0

  for (const seg of segs) {
    for (const w of words) {
      if (w.end <= seg.start || w.start >= seg.end) continue
      const start = Math.max(w.start, seg.start)
      const end = Math.min(w.end, seg.end)
      out.push({
        word: w.word,
        start: elapsed + (start - seg.start),
        end: elapsed + (end - seg.start),
      })
    }
    elapsed += seg.end - seg.start
  }
  return out
}
```

Boucler sur les segments **à l'extérieur** est ce qui garantit l'ordre croissant : les mots
sortent dans l'ordre des segments, pas dans celui de la source.

```python
import argparse, json, os, sys
import whisperx

def main():
    p = argparse.ArgumentParser()
    p.add_argument('--audio', required=True)
    p.add_argument('--out', required=True)
    p.add_argument('--model', default='large-v3')
    p.add_argument('--language', default='fr')
    a = p.parse_args()

    device = 'cuda'
    model = whisperx.load_model(a.model, device, compute_type='float16')
    audio = whisperx.load_audio(a.audio)
    result = model.transcribe(audio, batch_size=16, language=a.language)

    model_a, metadata = whisperx.load_align_model(language_code=result['language'], device=device)
    aligned = whisperx.align(result['segments'], model_a, metadata, audio, device)

    segments = [{
        'start': s['start'], 'end': s['end'], 'text': s.get('text', ''),
        'words': [{'word': w.get('word', ''), 'start': w.get('start'), 'end': w.get('end')}
                  for w in s.get('words', []) if w.get('start') is not None],
    } for s in aligned['segments']]

    os.makedirs(os.path.dirname(a.out), exist_ok=True)
    with open(a.out, 'w', encoding='utf-8') as f:

if __name__ == '__main__':
```

Le proxy dans un `<video>`, qui saute les parties retirées : à `timeupdate`, si la position
sort du segment courant, sauter au début du suivant. Spec §16 le dit : cela produit un
à-coup à chaque saut, acceptable pour juger, pas pour valider un rendu final.

- [ ] **Step 4 : Le choix du cadre, à la main**

Un sélecteur de ratio (`9:16`, `4:5`, `1:1`, `16:9`) et un rectangle **pleine hauteur** du
ratio choisi, superposé à l'image du proxy, déplaçable horizontalement seulement. Il écrit
`ratio` et `cropX`. Verticalement il n'y a rien à régler : le crop prend toute la hauteur.

Ce réglage manuel n'est pas un pis-aller jetable — il reste ensuite comme réglage de dernier
recours, et l'automatique de l'itération 1 ne fera que le préremplir.

- [ ] **Step 5 : Vérification à l'œil, puis commit**

Ouvrir un clip, retirer une phrase du milieu, vérifier que la durée baisse et que le lecteur
saute le passage. Régler le cadre en 1:1, décaler à gauche.

## Vérification de bout en bout

Une fois les quatorze tâches passées, la chaîne complète sur une émission jamais traitée :

```bash
# 1. Le CI est vert
gh pr checks

# 2. Ingestion et analyse complète, depuis le Drive
curl -s -X POST localhost:3000/api/projects -H 'content-type: application/json' \
  -d '{"source":"2025-11-09-realisateur.mp4"}' | jq -r .projectId

# 3. Suivre — compter environ 12 min de proxy puis 20 min de transcription
watch -n 10 "curl -s localhost:3000/api/projects/2025-11-09-realisateur | jq '.step, .progress'"

# 4. Trier dans l'interface, monter un clip, exporter

# 5. Le saut d'étape : relancer le repérage seul
curl -s -X POST localhost:3000/api/projects/2025-11-09-realisateur/run \
  -H 'content-type: application/json' -d '{"target":"candidates","force":["candidates"]}'
```

L'étape 5 doit rendre de nouveaux candidats **en une minute** et ne pas retranscrire. Si elle
retranscrit, le graphe est cassé et c'est la seule chose qui rende le projet inutilisable au
quotidien.

Et les clips gardés à l'étape 4 doivent **survivre** à l'étape 5.
